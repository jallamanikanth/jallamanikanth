# How this profile works

`README.md` is what renders on <https://github.com/jallamanikanth>. It embeds
two generated SVGs:

| File | What it is |
| --- | --- |
| `light.svg` / `dark.svg` | Animated terminal card — ASCII portrait on the left, system/contact readout on the right. README picks one with `<picture>` based on the viewer's theme. |
| `dist/github-jet.svg` | Animated jet flying over your real contribution grid. |

Both are regenerated by GitHub Actions and committed back to the repo.

## Repo layout

```
github-profile/
  profile.config.json   ← all card copy lives here (edit this)
  portrait.txt          ← 90×45 ASCII portrait
  generate-card.mjs     ← renders light.svg + dark.svg
  generate.mjs          ← renders dist/github-jet.svg from real contributions
.github/workflows/profile.yml   ← must live at the repo ROOT or GitHub never runs it
```

## Run it locally

```bash
node generate-card.mjs                          # card only, no network
GH_USERNAME=jallamanikanth node generate.mjs    # real contributions, no token needed
npm run build                                   # both
```

Preview the heatmap design without network access:

```bash
SAMPLE=1 GH_USERNAME=jallamanikanth node generate.mjs
```

The heatmap generator uses the GraphQL API when `GH_TOKEN` is set and falls
back to GitHub's public contributions calendar when it is not.

## One-time setup

1. The repo must be named exactly the same as your username
   (`jallamanikanth/jallamanikanth`) — that is what makes its README appear on
   your profile.
2. **Settings → Actions → General → Workflow permissions** → *Read and write
   permissions*, so the workflow can commit the regenerated SVGs.
3. **Actions** tab → *Update profile assets* → **Run workflow** once to produce
   the first versions.

## Contribution data

The heatmap counts **public** contributions only, using the workflow's built-in
`GITHUB_TOKEN`. Nothing else needs configuring.

## Updating the card

Everything on the card comes from `profile.config.json`. Edit the `sections`
array, re-run `node generate-card.mjs`, and commit the new SVGs (or let the
workflow do it on push).

To swap the portrait, replace `portrait.txt` with your own ASCII art — roughly
90 columns wide works best; the renderer reads the line count from the file.

## Customising the heatmap

In `generate.mjs`:

- `MAX_TARGETS` — how many of your busiest days get the bullet/blast effect
- `LOOP_DUR` — seconds for one flight (there and back)
- `FLASH_COLOR`, `BULLET_COLOR`, `BLAST_COLOR` — accent colours
- `COLS` / `ROWS` — grid size (34×7 matches GitHub's own layout)
